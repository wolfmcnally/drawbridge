# Licensing and the standalone boundary

Drawbridge source is MIT; LICENSE and NOTICE accompany its project artifacts. Its runtime wheel contains Python source/notices and separately installs dependencies with independent licenses, including public MIT Conric 0.1.0 at its exact recorded Git commit. PDF parsing/rendering/OCR/native typography belong to independently installed **Vellric**, AGPL-3.0-only, through complete document jobs. This candidate targets public regular Vellric v0.2.4 at commit `8b410165a52b246e72dc2ac326ce9e289c80aa43`, using the release wheel and matching source archive pinned by artifact hashes. Cloud-vision human acceptance and Windows desktop acceptance remain open upstream. Drawbridge imports/installs neither Vellric nor PyMuPDF in its runtime. Pillow owns non-PDF images.

PyMuPDF remains a development-only fixture/lock-test dependency. Existing external consumers that own native engine objects retain their own obligations and use the real PDF_LOCK/pdf_locked exports until migrated. Quillric is an optional audio distribution with its own notices, compatibility import namespace and provider requirements.

The source archive includes unmodified public fixtures. Their CC-BY-SA-4.0/IETF grants, original sources/hashes and attribution remain in tests/fixtures/MANIFEST.md, NOTICE and LICENSES/CC-BY-SA-4.0.txt. MIT does not overwrite those grants. The full CC text is retained from [SPDX primary license data](https://github.com/spdx/license-list-data/blob/main/text/CC-BY-SA-4.0.txt).

As of 2026-11-08, PDF page-citation integration targets the public Vellric 0.2.4 release described above. Cloud-vision qualification is not claimed. Matching wheel/source/lock/build material and notices stay together. The retained distribution metadata uses an exact Git dependency rather than a package-index-only dependency set. Live consumer upgrades remain separately authorized. Selected product briefs, historical plans and product tests accompany the source archive; current private methodology evidence does not. See [page-citation identity and rendering limits](PAGE-CITATIONS.md).

The PowerPoint release candidate separately installs python-pptx 1.0.2 (MIT), lxml 6.1.3 (BSD-3-Clause plus the selected wheel's component notices), and XlsxWriter 3.3.1 (BSD-2-Clause), reusing the existing Pillow and typing_extensions pins. Exact notices and relied-on source excerpts are cataloged under [references](../references/README.md). Drawbridge's wheel and source archive do not vendor these dependencies' native binaries. Installing a dependency wheel is distinct from redistributing a combined application bundle.

The selected macOS lxml wheel lists zlib, iconv, libxml2, libxslt and libexslt. Its notices identify iconv under LGPL 2.1, alongside the other components' independent grants; the entire native stack must not be described as MIT/BSD-only. lxml also identifies ElementTree/PSF and other exceptions in its LICENSES notice. Anyone redistributing dependency binaries must retain their notices and satisfy the applicable source/relinking and other obligations for the actual artifacts they distribute. The initial PowerPoint path adds no LibreOffice, rendering service, Vellric import or AGPL PDF-engine runtime dependency.

A downloaded public lecture deck was used only as private qualification input under its recorded terms. Neither it nor its mirrors/assets are in the source or distribution allowlist. Public examples and tests author their own small synthetic decks. Extraction defaults do not grant permission to publish presenter notes.

Drawbridge 0.3.1 retains these independently installed dependency boundaries. Source qualification and installed tests do not themselves establish public publication; the release workflow verifies the actual signed tag and downloaded artifact identity separately.

The native-component inventory above is scoped to the selected macOS wheel. Linux selects a separate manylinux aarch64 lxml artifact; consult that installed distribution’s LICENSES.txt and licenses directory for its actual bundled components and grants rather than applying the macOS inventory to it. Neither dependency wheel is redistributed inside Drawbridge.
