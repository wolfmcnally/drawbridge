## 2026-11-20 — END (correction) — portable digest check in the qualification workflow

The asset fetch in `.github/workflows/qualification.yml` now names standard input explicitly when it checks a download's digest: `sha256sum --check --status -`.

Follow-up route:
- Small low-risk inter-phase correction, approved by the Starter hub acting as the operator's coordinator on 2026-11-20 as the only product-side change in this window: the one proven line, unsigned, through this repository's ordinary checks. No inserted phase is needed for one operand on one line. Completed phase history, earlier reviews and consumed allowances remain unchanged.

Cause:
- `tests/test_qualification_workflow.py` runs the workflow's own inline Bash with the host's real `sha256sum`. On macOS 27.2.1 that is `/sbin/sha256sum` ("sha256sum (Darwin) 1.0"), which refuses check mode with no file operand, so both `test_transient_asset_recovers` cases failed on that host at a66ce18 before any other change. GNU coreutils reads standard input when given `-`, as the Darwin tool does, so the explicit operand gives the same result on the Ubuntu runner and on macOS.
- On that host the digest-mismatch refusal case had been passing for the wrong reason: every check refused, matching digest or not. With the operand, a matching digest passes and a wrong one is refused, so the refusal is now discriminating there too.

Files changed:
- `.github/workflows/qualification.yml` — one operand on the fetch helper's digest check; the expected digest, the size check, the refusal message and the retry bounds are unchanged. The other `sha256sum --check` lines run only on the Ubuntu runner and are unchanged.
- This immutable correction entry.
